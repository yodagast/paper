# Improving Text Embeddings with Large Language Models

## 基本信息
- **论文标题**: Improving Text Embeddings with Large Language Models
- **作者**: Liang Wang, Nan Yang, Xiaolong Huang, Linjun Yang, Rangan Majumder, Furu Wei (Microsoft)
- **发表时间**: 2023年12月 (arXiv), 2024年5月 (ACL 2024)
- **论文链接**: https://arxiv.org/abs/2401.00368

## 核心贡献

本文提出了一种**简单但高效**的方法，仅使用**合成数据**和**不到1k训练步数**，即可获得高质量的文本嵌入。该方法突破了传统多阶段复杂训练流程的限制，在BEIR和MTEB基准测试上取得了SOTA性能。

## 方法详解

### 1. 合成数据生成 (Synthetic Data Generation)

#### 核心思想
利用GPT-4等专有LLM生成多样化、高质量的合成训练数据，覆盖：
- **93种语言**
- **数十万文本嵌入任务**
- 多种任务类型（检索、相似度、聚类等）

#### 两阶段提示模板 (Two-Step Prompting)

**第一步 - 头脑风暴 (Brainstorming)**:
```
任务: 列出潜在的检索任务类型
输出: 任务列表 (如FAQ检索、代码搜索、科学文献检索等)
```

**第二步 - 数据生成**:
```
任务: 为每个任务生成 (query, positive, hard_negative) 三元组
输入: 任务定义 + 随机采样的占位符参数
输出: JSON格式的训练样本
```

#### 任务分类与提示设计

**对称任务 (Symmetric Tasks)**:
- 查询和文档语义相似但表面形式不同
- 包括：单语言语义文本相似度(STS)、双语平行文本检索
- 使用专门的提示模板，无需头脑风暴步骤

**非对称任务 (Asymmetric Tasks)**:
- 查询和文档语义不同（如问答检索）
- 使用两阶段提示模板
- 包含任务特定的指令

#### 多样性增强策略
- **占位符随机采样**: 如 `{query_length}` 从 `{少于5词, 5-10词, 至少10词}` 中采样
- **语言采样**: 从XLM-R语言列表中采样，高资源语言权重更高
- **数据清洗**: 丢弃格式错误的JSON，基于精确字符串匹配去重

### 2. 模型训练

#### 模型架构
- **骨干网络**: Mistral-7B (Decoder-only LLM)
- **输入处理**: 在查询和文档末尾添加 `[EOS]` token
- **嵌入提取**: 使用最后一层的 `[EOS]` 向量作为嵌入表示

#### 指令模板 (Instruction Template)

对于查询端，应用以下模板：
```
Instruct: {task_definition}
Query: {original_query}
```

**关键设计**:
- **仅查询端加指令**: 文档端不加指令前缀
- **优势**: 可预构建文档索引，通过修改查询指令即可定制任务
- **任务定义**: 一句话描述嵌入任务（合成数据使用头脑风暴输出，真实数据手工编写）

#### 损失函数: InfoNCE Contrastive Loss

$$
\min \mathcal{L} = -\log \frac{\phi(q_{inst}^+, d^+)}{\phi(q_{inst}^+, d^+) + \sum_{n_i \in \mathbb{N}} \phi(q_{inst}^+, n_i)}
$$

其中:
- $\phi(q, d) = \exp(\frac{\text{sim}(q, d)}{\tau})$: 相似度得分
- $\text{sim}(q, d) = \frac{h_q^T h_d}{\|h_q\| \|h_d\|}$: 余弦相似度
- $\mathbb{N}$: In-batch负样本 + 困难负样本
- $\tau$: 温度参数

### 3. 训练细节

- **训练步数**: < 1k steps
- **数据**: 纯合成数据 或 合成数据+标注数据混合
- **上下文长度**: 可扩展到32k tokens (通过修改位置编码的rotation base)

## 实验结果

### 主要发现

1. **纯合成数据训练**: Mistral-7B仅在合成数据上微调，即可在BEIR和MTEB上取得有竞争力的性能
2. **混合训练**: 合成数据+标注数据混合训练，在BEIR和MTEB上取得新的SOTA，超越之前方法约2%
3. **长上下文**: 可有效处理32k tokens的个性化passkey检索任务

### 多语言能力
- **高资源语言**: 表现优异
- **低资源语言**: 仍有改进空间（开源LLM预训练数据不足）

## 创新点与优势

### 相比传统方法

| 方面 | 传统方法 (E5, BGE) | 本文方法 |
|------|-------------------|----------|
| 训练流程 | 多阶段复杂流程 | 单阶段简单训练 |
| 数据依赖 | 数十亿弱监督文本对 + 人工标注 | 纯合成数据 |
| 任务多样性 | 受限于人工收集 | 数十万多样化任务 |
| 语言覆盖 | 主要高资源语言 | 93种语言 |
| 模型架构 | BERT-style encoder | Decoder-only LLM |

### 关键优势
1. **简单性**: 无需复杂的训练管道
2. **可扩展性**: 轻松扩展到新语言和任务
3. **高质量**: 合成数据质量高，多样性丰富
4. **长上下文**: 天然支持长文本处理

## 局限性与未来方向

1. **低资源语言**: 性能受限于基础LLM的多语言能力
2. **计算成本**: 需要调用专有LLM生成数据
3. **领域适应性**: 特定领域可能需要领域特定的合成数据策略

## 实践启示

1. **合成数据是强有力的训练资源**: 高质量的合成数据可以替代或补充人工标注
2. **Decoder-only LLM适合嵌入任务**: 通过适当微调，大语言模型可以产生高质量的文本嵌入
3. **指令微调增强灵活性**: 单侧指令设计使得同一文档索引可服务多种任务
4. **多样性是关键**: 任务和语言的多样性对模型泛化能力至关重要
