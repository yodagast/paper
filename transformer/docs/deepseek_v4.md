## 2. 架构创新

### 2.1 继承自 DeepSeek-V3 的设计

- **DeepSeekMoE**：沿用细粒度路由专家 + 共享专家范式
  - 变更：激活函数从 `Sigmoid(·)` 改为 `Sqrt(Softplus(·))`
  - 负载均衡：采用无辅助损失策略 + 轻量序列级平衡损失
  - 前几层使用 Hash Routing 替代密集 FFN
  - 移除了路由目标节点数量约束，重新设计并行策略
- **多Token预测（MTP）**：与 V3 配置完全一致

### 2.2 流形约束超连接（Manifold-Constrained Hyper-Connections, mHC）

**核心问题**：标准残差连接在万亿参数深度网络中存在信号放大或坍缩风险。

**标准超连接（HC）**：将残差流宽度扩展 $n_{hc}$ 倍，残差状态从 $R^d$ 扩展为 $R^{n_{hc} \times d}$。

**mHC 关键创新**：
- 将残差映射的混合矩阵约束到 **Birkhoff 多面体（Birkhoff Polytope）** 上
- 使用 **Sinkhorn-Knopp 算法** 确保混合矩阵始终位于双随机矩阵流形上
- 效果：保持信号幅度在网络中稳定传播，增强深层网络的数值稳定性
- 实现上：约30行 PyTorch 代码的改动，可推广到任何使用残差连接的架构

### 2.3 混合注意力架构（Hybrid CSA + HCA）

这是 V4 最核心的架构创新，彻底解决了标准注意力机制 $O(n^2)$ 的计算瓶颈。

#### 2.3.1 压缩稀疏注意力（Compressed Sparse Attention, CSA）

**设计思路**：对 KV Cache 沿序列维度压缩后，进行稀疏选择注意力。

**工作流程**：
1. **KV 压缩**：以 $m$ 倍压缩率（如4x）将 KV 条目沿序列维度压缩
   - 使用可学习压缩权重进行加权聚合
   - 支持重叠压缩以保持边界信息
2. **闪电索引器（Lightning Indexer）**：
   - 对压缩后的索引键进行低秩查询
   - 计算每个 query 与各压缩块的索引分数
   - 使用 top-k 选择器保留最相关的压缩 KV 条目
   - 索引计算在 FP4 精度下执行，极大加速长上下文场景
3. **共享 Key-Value MQA**：
   - 选出的压缩 KV 条目同时作为 key 和 value（共享）
   - 使用多查询注意力（MQA）方式执行核心注意力计算
4. **分组输出投影**：将多头输出分组投影，降低计算开销

#### 2.3.2 重度压缩注意力（Heavily Compressed Attention, HCA）

**设计思路**：更激进的压缩 + 密集注意力，提供全局粗粒度视图。

- 压缩率 $m'$ 远大于 CSA（如128x）
- 不执行稀疏选择，对压缩后表示进行密集注意力
- 每层提供"广角镜头"式的全局上下文感知
- 与 CSA 层交替排列：**精确检索 ↔ 全局概览**

#### 2.3.3 其他注意力细节

- **部分旋转位置编码（Partial RoPE）**：对 query、KV 条目和核心注意力输出的最后64维应用 RoPE
- **滑动窗口注意力分支**：补充最近的 $n_{win}$ 个未压缩 KV 条目，保持局部依赖建模和严格因果性
- **注意力汇（Attention Sink）**：引入可学习的 sink logits，允许注意力分数和不严格为1，甚至接近0
- **混合精度 KV 存储**：RoPE 维度用 BF16，其余用 FP8，KV Cache 近乎减半

#### 2.3.4 效率对比

以 BF16 GQA8（head dim=128）为基线，V4 在 1M 上下文下 KV Cache 仅为基线的约 **2%**。

## 3. Muon 优化器

V4 将大部分参数的优化器从 AdamW 切换为 **Muon**，实现更快收敛和更稳定的训练。

### 算法流程

```
对每个逻辑独立的权重 W：
1. 计算梯度 G_t = ∇_W L_t
2. 累积动量 M_t = μ·M_{t-1} + G_t
3. Nesterov 技巧 + 混合 Newton-Schulz 正交化 O'_t
4. 重缩放更新 RMS: O_t = O'_t · √(max(n,m)) · γ
5. 权重衰减和更新: W_t = W_{t-1}·(1-ηλ) - η·O_t
```

### 关键设计

- **混合 Newton-Schulz 迭代**：分两阶段
  - 前8步：系数 (3.4445, -4.7750, 2.0315) 快速收敛
  - 后2步：系数 (2, -1.5, 0.5) 精确稳定奇异值到1
- **保留 AdamW 的模块**：Embedding、预测头、RMSNorm、mHC 的静态偏置和门控因子
- **避免注意力 logits 爆炸**：V4 的注意力架构允许直接对 query 和 KV 条目应用 RMSNorm，因此无需 QK-Clip 技术
- **峰值学习率**：2.0e-4（Pro），余弦衰减

## 4. 基础设施优化

### 4.1 细粒度专家并行通信-计算重叠

- 核心洞察：MoE 层中通信延迟可被计算完全隐藏
- 将专家分为多个 wave，实现通信-计算流水线
- 理论加速比达 1.92x（对比 Comet 的 1.42x）

### 4.2 TileLang 内核开发

- 基于 DSL 的高效内核开发框架，兼顾开发效率与运行时性能
- **Host Codegen**：将 host 端逻辑移入生成代码，CPU 端开销从微秒级降至亚微秒
- **SMT 求解器辅助整数分析**：集成 Z3 进行形式化整数分析，解锁更深层优化
- **数值精度控制**：IEEE 合规内置函数、位级可复现性

### 4.3 批不变与确定性内核

- **批不变性**：同一 token 的输出无论在 batch 中位置如何，严格位级一致
  - 双内核策略：全占满波用单 SM 核，部分填充波用多 SM 核
- **确定性训练**：
  - 注意力反向传播：独立累积缓冲 + 全局确定性求和
  - MoE 反向传播：token 顺序预处理 + 跨 rank 缓冲隔离
  - mHC 矩阵乘法：split-k 部分单独输出 + 确定性归约

### 4.4 FP4 量化感知训练（QAT）

- **MoE 专家权重**：FP4 (MXFP4) 量化，前向用 FP8 模拟，反向直通估计器（STE）
- **CSA 索引器 QK 路径**：QK 激活全程 FP4，加速长上下文注意力分数计算
- **索引分数**：从 FP32 量化到 BF16，top-k 选择器 2x 加速，召回率保持 99.7%
- 推理/RL rollout 阶段直接使用真实 FP4 权重，与在线部署行为完全一致

### 4.5 训练框架

- **Muon + ZeRO 混合策略**：
  - 密集参数：限制 ZeRO 并行度最大值 + 背包算法分配
  - MoE 参数：独立优化每个专家，展平后均匀分配
  - 同形状参数自动合并，批处理执行
- **mHC 高效实现**：成本效益和内存效率优化
- **上下文并行**：长上下文注意力的上下文并行策略
- **扩展自动微分**：灵活的激活检查点

### 4.6 推理框架

- **KV Cache 结构与管理**：混合存储格式（BF16 + FP8），磁盘 KV Cache 存储
  - 三种 SWA KV 管理策略：全缓存 / 周期检查点 / 零缓存
- **WAL（Write-Ahead Log）**：token 级粒度的预写日志，支持抢占后精确恢复

## 5. 预训练

### 5.1 数据构建

- 在 V3 预训练数据基础上，构建更多样、更高质量的训练语料
- 分词器：沿用 V3 的 128K 词表 + 新增上下文构建特殊 token
- 继承 token-splitting 和 FIM 策略
- 跨源文档打包：将不同来源文档打包到合适序列中

### 5.2 训练不稳定性缓解

- **动态数据跳过**：检测到异常时动态跳过问题数据，几乎无额外训练开销
- **SwiGLU Clamping**：
  - 线性分量钳制到 [-10, 10]
  - 门控分量上限设为 10
  - 有效消除异常值，稳定训练过程

## 6. 后训练

### 6.1 专家训练（Specialist Training）

两阶段培养领域专家：

1. **SFT**：高质量领域特定数据监督微调
2. **GRPO 强化学习**：使用 Group Relative Policy Optimization，配合领域定制奖励模型

**推理力度（Reasoning Effort）**：三种模式

| 模式 | 特点 | 适用场景 |
|------|------|---------|
| Non-think | 快速直觉响应 | 日常任务、低风险决策 |
| Think High | 有意识逻辑分析 | 复杂问题、规划 |
| Think Max | 推理极限 | 探索模型推理边界 |

- Think Max 模式在系统提示前注入特殊指令，引导模型彻底分解问题
- 使用 `` 和 `` token 划分推理路径

**生成式奖励模型**：难以验证的任务使用模型自身逻辑进行泛化

### 6.2 在策蒸馏（On-Policy Distillation, OPD）

**核心方法**：用多教师 OPD 替代 V3.2 的混合 RL 阶段，将多个领域专家能力合并到统一模型。

**目标函数**：

$$L_{OPD}(\theta) = \sum_{i=1}^{N} w_i \cdot D_{KL}(\pi_\theta \| \pi_{E_i})$$

**关键设计**：
- 学生模型在自己生成的轨迹上学习
- 反向 KL 散度确保学生从相关领域专家学习
- **全词表 logit 蒸馏**（非 token 级 KL 估计），梯度估计更稳定
- 超过10个教师模型参与蒸馏
- 教师隐藏状态缓存 + 按需预测头重构 logits，避免显式 logits 物化的内存负担

### 6.3 交错思考（Interleaved Thinking）

- **工具调用场景**：全对话保留推理内容，不因用户新消息而丢弃
- **一般对话场景**：保持 V3.2 策略，新用户消息到达时丢弃先前推理内容

### 6.4 快速指令（Quick Instruction）

- 在输入序列末尾追加特殊 token，复用已有 KV Cache
- 并行执行辅助任务（搜索触发、意图识别、标题生成等）
- 消除维护额外小模型的工程开销，显著降低 TTFT

### 6.5 工具调用模式

- 使用 `|DSML|` 特殊 token + XML 格式进行工具调用
- XML 格式有效减少转义失败和工具调用错误

## 9. 技术要点总结

1. **混合注意力是效率核心**：CSA（4x压缩+稀疏选择）提供精确检索，HCA（128x压缩+密集注意力）提供全局概览，两者交替实现次线性上下文扩展
2. **mHC 稳定深层训练**：Birkhoff 多面体约束确保万亿参数深度网络信号传播稳定，实现简洁且可推广
3. **Muon 优化器加速收敛**：混合 Newton-Schulz 正交化 + Nesterov 动量，比 AdamW 收敛更快
4. **FP4 QAT 前置量化**：训练阶段即引入 FP4 量化感知，推理无需后训练量化，质量无损
5. **OPD 替代混合 RL**：全词表 logit 蒸馏 + 多教师反向 KL，稳定合并多个领域专家到统一模型
6. **全栈基础设施协同**：从内核开发（TileLang）到训练框架（ZeRO+Muon 混合）到推理服务（KV Cache 管理+WAL），系统性优化
7. **1M 上下文原生效用**：架构+精度优化使百万 token 上下文从理论可行变为工程可负担，为长程任务和 test-time scaling 奠定基础
